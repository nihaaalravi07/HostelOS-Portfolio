# REST API

Base path `/api`, JSON in and out. Interactive documentation is generated by springdoc at **`/swagger-ui.html`** (OpenAPI JSON at `/v3/api-docs`) and always reflects the running code; this file is a readable summary. The endpoint list below was taken from the `@PreAuthorize` annotations of the controllers.

## Authentication

Obtain a token with `POST /api/auth/login`, then send it on every other request:

```http
Authorization: Bearer <token>
```

Tokens are HS256 JWTs valid for 12 hours. Role names: `STUDENT`, `WARDEN`, `ADMIN`, `MESS_STAFF`, `HOUSEKEEPING_STAFF`, `MAINTENANCE_STAFF`. A resident's identity always comes from the token.

```bash
curl -s http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"aarav.sharma@iiita.ac.in","password":"hostelos123"}'     # demo mode only
```

```json
{ "token": "<jwt>",
  "user": { "id": 8, "email": "aarav.sharma@iiita.ac.in", "fullName": "Aarav Sharma", "role": "STUDENT" } }
```

## Errors

Every error has the same body, `{"message": "..."}`.

| Status | Meaning | Example |
|---|---|---|
| 400 | Invalid input or malformed JSON | `{"message":"description must not be blank"}` |
| 401 | Missing or invalid token, wrong credentials | `{"message":"Please sign in"}` |
| 403 | Role not allowed, or not the owner of the record | `{"message":"You do not have permission to do this"}` |
| 404 | Unknown id | `{"message":"..."}` |
| 409 | Illegal state change, duplicate, or a database constraint was hit | `{"message":"Consumption was already confirmed for this booking"}` |

There is no catch-all handler, so an unexpected exception is answered with Spring's default 500 response.

## Endpoints

"Any" means any authenticated user; "public" needs no token.

### Authentication and users

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/api/auth/login` | public | Body `{email, password}`; returns token and user |
| GET | `/api/auth/me` | any | The signed-in user |
| GET | `/api/auth/demo-accounts` | public | Demo accounts for the login screen; empty list unless `DEMO_MODE=true` |
| GET | `/api/users` | ADMIN | All users |
| GET | `/api/users/staff` | ADMIN, WARDEN | Staff members (for assigning work) |
| GET | `/healthz` | public | `{"status":"ok"}`; used as the hosting health check |

### Meals (student)

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/api/meals` | STUDENT | Menu for the coming days with the caller's booking status |
| GET | `/api/meals/history` | STUDENT | The caller's bookings |
| POST | `/api/meals/{id}/book` | STUDENT | Book a meal (also re-books a cancelled one); fails with 409 after the cutoff |
| POST | `/api/meals/{id}/cancel` | STUDENT | Cancel before the cutoff |
| POST | `/api/meals/{id}/feedback` | STUDENT | Body `{tasteRating 1-5, hygieneRating 1-5, comment}`; only for a meal the student ate |

Example: booking a meal returns the meal with the caller's status. Booking does **not** create a charge.

```json
{ "id": 60, "date": "2026-11-21", "category": "DINNER", "categoryLabel": "Dinner",
  "startTime": "20:00:00", "endTime": "21:30:00",
  "menuItems": ["Roti", "Veg biryani", "Raita", "Dal makhani"], "price": 90.00,
  "cutoffTime": "2026-11-21T23:59:00", "bookingOpen": true, "available": true,
  "myStatus": "BOOKED", "myBookingId": 881, "ratingCount": 0 }
```

### Mess operations

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/api/mess/board` | MESS_STAFF, ADMIN | Today's meals with counts (booked, consumed, cancelled, missed, expected, pending, revenue) and bookings |
| POST | `/api/mess/bookings/{id}/confirm` | MESS_STAFF, ADMIN | Confirm that the resident ate: marks `CONSUMED` and posts exactly one charge, in one transaction |
| POST | `/api/mess/meals/{id}/close-no-shows` | MESS_STAFF, ADMIN | Close remaining bookings of a meal as `MISSED` (no charge) |
| PUT | `/api/mess/meals/{id}` | MESS_STAFF, ADMIN | Body `{menuItems, price, cutoffTime, available}` |
| GET | `/api/mess/menu` | MESS_STAFF, ADMIN | Menu for editing |
| GET | `/api/mess/feedback` | MESS_STAFF, ADMIN | Food feedback |
| GET | `/api/mess/analytics` | MESS_STAFF, ADMIN | Rating distribution, popular and poorly rated meals, expected vs eaten |

Confirming a booking:

```json
{ "bookingId": 881, "residentId": 1, "residentName": "Aarav Sharma", "enrollmentNo": "IIT2023001",
  "status": "CONSUMED", "bookedAt": "2026-11-21T00:10:13.521207", "consumedAt": "2026-11-21T00:10:13.6175",
  "chargedAmount": 90.00 }
```

Confirming the same booking again returns `409 {"message":"Consumption was already confirmed for this booking"}` and posts nothing.

## Notes

- Request fields marked with limits are validated with Bean Validation; a violation gives `400`.
- Response shapes for the dashboards and reports are the records in the `dashboard`, `finance` and `mess` packages; the Swagger UI shows their full schema.
- The CORS configuration allows `http://localhost:*` and `http://127.0.0.1:*` only. In the production image the UI is served from the same origin.
